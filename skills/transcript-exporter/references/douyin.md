# 抖音视频采集细节

## 平台判断与工具选择

- **Mac**：`mac_computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- **Windows**：`computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- 两者 API 完全一致：`bu.navigate()`、`bu.wait_for_load()`、`bu.snapshot()`、`bu.get_page_text()`、`bu.find()`、`bu.click()`

## 登录检测与处理

### 登录态判断标志
- 页面顶部显示"登录"按钮 → 未登录
- 作品列表区域显示"服务异常，重新刷新拉取数据" → 未登录或登录过期
- 作品列表正常显示视频卡片（含封面、标题、点赞数）→ 已登录

### 未登录处理
1. 不要尝试自动输入手机号/验证码，抖音有滑块验证和短信验证。
2. 立即调用 `interaction.request_action`：
   ```python
   interaction.request_action(
       type="browserControl",
       display_message="抖音页面需要登录才能查看完整作品列表。请接管浏览器完成扫码或验证码登录，登录完成后把控制权交回。"
   )
   ```
3. 用户交回后，重新 `bu.snapshot()` 确认作品列表已加载。

## 采集节奏控制（强制）

全程模拟真人操作，降低被风控识别的概率：

- **随机延迟**：所有 `time.sleep()` 一律使用 **2~5 秒随机延迟**：`time.sleep(random.uniform(2, 5))`，禁止固定 sleep(2) 或快速连续操作。
- **规模控制**：同一博主单次采集建议 ≤10~20 条；用户未指定时保持默认 5 条。
- **采集时段**：白天分散采集，避免深夜/凌晨高频操作。
- **采集间隔**：不同博主之间间隔 1 小时以上；同一博主重复采集前先做增量去重，避免无意义重复访问。
- **登录纪律**：使用独立小号 + 固定设备环境；登录一次后保持登录态，不反复退出重登（频繁异地登录/反复登录是风控信号）。

## 主页视频列表提取

### 方法一：从页面文本提取（推荐）
登录后，`bu.get_page_text()` 返回的文本中包含每条视频的完整信息：
```
置顶
3091

你越强势，AI可能越蠢 很多人以为，把要求、步骤和标准...
```
- 数字 = 点赞数
- 第一行文字 = 标题 + 文案（以空格分隔）
- 视频链接需从 DOM 的 `href` 属性提取

### 方法二：从 DOM 提取视频链接
用 `bu.read_all()` 或 snapshot 中的 ref 提取所有 `/video/xxxxx` 链接：
```python
videos = bu.read_all(
    "a[href*='/video/']",
    fields=["href", "text"],
    limit=100,
)
```
- 去重：同一视频可能在"作品"和"推荐"区域重复出现，按 video_id 去重。
- 置顶视频会标注"置顶"，但 video_id 仍可正常提取。

### 滚动加载全部视频
抖音主页默认只加载前几条，需要向下滚动触发懒加载：
```python
import random

# 滚动到底部，等待加载，重复直到没有新视频
for _ in range(10):
    bu.scroll(500, 500, "down", amount=3)
    time.sleep(random.uniform(2, 5))  # 随机延迟，模拟真人
    # 检查是否出现"暂时没有更多了"
```
- 页面底部出现"暂时没有更多了" → 全部加载完成。
- 博主视频较多时（>50条），滚动次数需相应增加。

### 主页全量排序落盘（分批采集复用规范）

滚动加载全部完成后，将提取到的全部视频按点赞数降序排序，保存为本地 JSON：

```json
{
  "author": "示例博主",
  "collected_at": "2026-09-25 20:00:00",
  "total": 299,
  "videos": [
    {"rank": 1, "video_id": "7635580570106408680", "url": "https://www.douyin.com/video/7635580570106408680", "title": "经典智慧 如何洞悉人心", "likes": 253000}
  ]
}
```

- **保存路径**：当前工作目录，文件名 `{博主昵称}_all_videos_sorted.json`（博主昵称含特殊字符时替换为下划线）。
- **复用规则**：用户要求"Top 1-20 / 21-40 / 41-60"等分批采集时，直接按落盘排序取对应区间，**不重新滚动扫描主页**；仅当用户明确要求最新数据或落盘文件缺失时才重扫。
- **零风险声明**：落盘保存是本地文件写入，与抖音账号无关，无风控风险。
- **重扫纪律**：不要在短时间内反复滚动加载同一博主主页（批量滚动属于批量读取行为，多次高频执行才可能被识别为异常）；确需核对数据更新时，间隔数周/月低频重扫一次即可。

### 断点续采（进度文件）

维护本地进度文件 `{博主昵称}_progress.json`，记录本次目标区间每条视频的采集状态：

```json
{
  "author": "示例博主",
  "targets": [
    {"video_id": "7635580570106408680", "url": "https://www.douyin.com/video/7635580570106408680", "status": "done", "detail_ok": true, "transcript_ok": true, "transcript_status": "success", "output_key": "local:douyin_data/示例博主_20260927_2条", "result_path": "示例博主_results/7635580570106408680.json", "file_path": "douyin_data/示例博主_20260927_2条/01_7635580570106408680.md", "updated_at": "2026-09-27 15:00:00"},
    {"video_id": "7495340723705777460", "url": "https://www.douyin.com/video/7495340723705777460", "status": "failed", "reason": "详情页加载超时", "updated_at": "2026-09-27 15:02:00"}
  ]
}
```

**状态机与持久化**：
- `pending`：本轮目标尚未完成输出。
- `done`：详情已采集、逐字稿成功（或用户不要/确认无口播），完整结果缓存已写入，且目标飞书记录或本地文件已写入并验证。
- `failed`：采集、逐字稿或输出失败；记录环节与原因，保留已经获取的数据。
- 进度另记 `output_key`（目标表格 base_token/table_id 或本地目录）、`record_id`/文件路径、`result_path`、`transcript_status`。用户切换输出目标时，不能按旧目标的 done 状态跳过交付。

**采集循环逻辑**：
1. 开始前合并当前目标与已有进度；新增目标初始化为 pending，保留历史目标状态，不覆盖已有进度。
2. 同一输出目标且 done 的视频跳过。failed 优先重试（本轮最多 1 次）；pending 正常处理。
3. 获取数据后立即把完整记录保存为本地结果缓存；缓存和进度使用临时文件写入后原子替换，避免中断写坏 JSON。
4. 从缓存写入目标表格或本地文件，验证成功后才标 done。输出失败保留缓存，下一轮先恢复写入，避免重新采集。
5. 逐字稿失败但基础数据成功时可以先输出基础数据，保持 failed 与明确原因；之后逐字稿补齐时按视频链接/record_id 更新同一条，不重复新增。
6. 用户明确不提取逐字稿或确认无口播时，记录 `transcript_status: skipped/not_applicable`；输出成功即 done，不反复重试。

**与增量去重的关系**：必须分页获取已有表格记录。去重仅跳过完整记录；失败或部分成功的记录在重试成功后更新同一 record_id。若进度为 done 但输出文件丢失或表格记录不存在，从缓存恢复输出。

## 视频详情页数据提取

### 页面结构
进入 `https://www.douyin.com/video/<video_id>` 后，`bu.get_page_text()` 返回：
```
00:01 / 07:57
...（章节要点，如有）
第2集 | 你越强势，AI可能越蠢 很多人以为...（完整文案）
3091
78
2177
543
举报
发布时间：2026-07-27 20:02
孟湄

粉丝4990获赞2.0万
```

### 数据字段映射
| 字段 | 提取方式 |
|------|----------|
| 标题 | 文案第一行，`\|` 或第一个空格之前的部分 |
| 介绍/文案 | 标题之后的完整文字，到互动数字之前 |
| 点赞 | 互动区第1个数字 |
| 评论 | 互动区第2个数字 |
| 收藏 | 互动区第3个数字（非必须采集） |
| 转发 | 互动区第4个数字 |
| 发表日期 | "发布时间：" 后的时间字符串 |
| 作者昵称 | 发布时间下方的作者名 |

### 数字格式处理
- 点赞/评论/转发可能显示为"1.6万"、"2.3万"等缩写。
- 转换规则：`1.6万` → `16000`，`2.3万` → `23000`。
- 小于1万的数字直接为整数。
- 写入飞书 number 字段时必须为整数，不能带"万"字。

### 批量提取效率
- 视频较多时，逐个导航+等待加载较慢。
- 可在一个浏览器 cell 中循环导航所有视频，减少 cell 调用开销：
  ```python
  import random

  for url in video_urls:
      bu.navigate(url)
      bu.wait_for_load(timeout=20)
      time.sleep(random.uniform(2, 5))  # 随机延迟，模拟真人
      page_text = bu.get_page_text()
      # 解析并存储
  ```
- 注意 cell 超时限制（默认120秒），视频超过5条时需分批或增大 `timeout_ms`。
- **批量控制**：单次循环建议不超过 10~20 条；批量采集量大时分多批执行，批与批之间间隔 1 小时以上。

## 逐字稿提取

### 【强制要求】完整性原则
- **必须获取完整逐字稿，禁止写任何占位符说明**（如"完整内容已通过web.fetch获取"、"内容已获取"等）。
- 如果获取失败，该字段留空并标注失败原因，绝不能用占位文字冒充完整内容。
- 写入后检查正文是否仅为占位说明；正常正文包含"完整内容"、"web.fetch"、"获取"等词时不单独判为失败。

### 快速路径（首选）
对每条视频 URL 调用 `web.fetch`，抖音页面返回的内容中包含完整逐字稿：
```
# 标题 + 文案...

你越强势，AI效果就越蠢。你一定听过一个观点...（完整逐字稿正文）
```
- 第一个空行之前 = 标题+文案
- 第一个空行之后 = 逐字稿正文
- 此方法无需下载视频，速度快，准确率高。

### web.fetch 分页读取（关键）
web.fetch 单次返回可能被截断，**必须检查并分页读取直到完整**：

1. 首次调用：`web.fetch(url=..., pagination={"offset": 0, "limit": 4000})`
2. 检查返回结果中的 `pagination_content`：
   - `start_offset`：本次读取起始位置
   - `end_offset`：本次读取结束位置
   - `total_length`：文档总长度
3. 如果 `end_offset < total_length`，说明内容被截断，**必须继续读取**：
   - 下一次调用设置 `pagination.offset = 上一次的 end_offset`
   - 重复直到 `end_offset >= total_length`
4. 将所有分页返回的 `pagination_content` 拼接为完整文本。若 end_offset 不增加、返回重复页或超过本次调用时间预算，停止并记录失败，不无限循环。

### 内容完整性判断标准
分页未读完、web.fetch 失败/返回空内容，或正文仅为占位说明时判为失败。少于 50 字或末尾缺标点只需复核，不直接丢弃短口播。正常正文出现"获取"、"完整内容"等词不构成失败。获取失败时逐字稿留空，缓存记录 `transcript_status: failed` 和原因；确认无口播时记录 `transcript_status: not_applicable`，不反复重试。回退规则如下，以主 Skill 的 Step 3 第4项为准。

### 回退路径（启用后 ≤3 条直接，>3 条整批确认）

**唯一规则入口**：`../SKILL.md` 的 Step 3 第4项。首次由使用者明确启用"下载音频并上传飞书妙记"；已有本任务授权不重复询问。待回退视频按 video_id 去重后汇总本任务整批数量：1~3 条在授权内直接执行，>3 条先确认整批范围，不按小批次规避确认。

- 仅 web.fetch 确实失败、未读完或返回占位正文时进入候选列表；短正文、无标点、正常出现"获取"等词不单独触发。
- `doubao-video-extract` 是外部可选依赖，不随本仓库分发；执行前先读取其说明并确认脚本路径与本人飞书授权。缺失或无权限时保留已采数据并说明原因。
- 此路径会下载音频并上传飞书妙记，即使最终结果只保存本地也一样；用户禁止下载、禁止上传或不要逐字稿时跳过。
- 每条最多回退一次；成功记录 `transcript_source: feishu_minutes`，更新已有记录/文件并验证，失败保存原因，不重复新增、不无限重试。

```bash
# 先读取外部 doubao-video-extract Skill 的说明，确认目录与依赖
cd <doubao-video-extract Skill目录>
python3 scripts/minutes/social_video_to_minutes.py "<视频URL>" --run-lark
```

### 不提取逐字稿的情况
- 用户明确说"只要基础数据"、"不要逐字稿"
- 视频是纯音乐/无口播内容（可从文案判断）
- 此时逐字稿字段留空字符串。

## 常见异常处理

| 异常 | 原因 | 处理 |
|------|------|------|
| 作品列表显示"服务异常" | 未登录或登录过期 | 请求用户接管重新登录 |
| 视频详情页加载超时 | 网络慢或抖音限流 | 增加 wait 时间，重试1-2次 |
| 互动区数字缺失 | 视频刚发布，数据未统计 | 未知值留空并标注；只有页面明确显示0才填0 |
| 逐字稿返回为空 | 视频无字幕/无口播 | 确认无口播则标注 not_applicable；无法确认且获取失败时按主 Skill 的整批回退规则处理 |
| 逐字稿被截断/写了占位符 | web.fetch 未分页读取，或写入了"完整内容已获取"等占位文字 | **禁止写占位符**；必须分页读取 web.fetch 直到完整；仍不完整则留空标注（妙记回退按主 Skill Step 3 第4项，启用后整批计数）；写入后验证正文不是整段占位说明 |
| 页面跳转登录页 | 登录态失效 | 重新请求用户登录 |
